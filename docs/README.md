# 文档索引

本目录存放模组的**规范类文档**；面向玩家的简介、历史与工程约定仍在仓库根目录。

| 文档 | 内容 | 主要读者 |
| --- | --- | --- |
| [README](../README.md) | 模组简介、玩法速览、构建与安装 | 玩家 / 使用者 |
| [SPEC](SPEC.md) | 行为规范：状态机、听觉、攻击、声波、数值表、验收用例 | 策划 / 测试 / 开发者 |
| [API](API.md) | 接口：注册 ID、Java 成员、Mixin、资源契约、稳定度 | 二次开发 / 维护者 |
| [AGENTS](../AGENTS.md) | 工程约定：环境、结构、不变量、踩坑、验证、提交 | 协作者 / AI |
| [CHANGELOG](../CHANGELOG.md) | 版本变更记录 | 所有人 |

## 阅读顺序

1. 只想玩：读 [README](../README.md) 的「快速开始」与「玩法速览」。
2. 想改行为/数值：读 [SPEC](SPEC.md) 的状态机与数值总表，再动代码。
3. 想接 API/改资源：读 [API](API.md) 的稳定度分级与资源契约。
4. 要提交代码：读 [AGENTS](../AGENTS.md) 的不变量与踩坑，跑完验收用例。

## 维护规则

- **单一事实来源**：行为与数值以 SPEC 为准；接口与 ID 以 API 为准；README 只做摘要，不重复细节。
- **同改同测**：改行为 → 先改 SPEC，再改代码，最后补 CHANGELOG；改 ID/资源键 → 同步 API 与 CHANGELOG；改用户可见功能 → 同步 README。
- **数值引用常量名**：表格里写 `SONIC_RANGE` 这类常量名和当前值，避免出现"文档 40、代码 32"的漂移。
- **链接可点**：文档之间用相对路径互相引用，标题锚点保持稳定（改标题时同步目录与锚点）。
- **语言**：正文用简体中文；ID、类名、方法签名、JSON 字段保持英文原文。
- **验收可执行**：SPEC 的验收用例必须能照做，新增规则时补用例，而不是只改描述。
